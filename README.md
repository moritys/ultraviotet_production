# Ultraviolet Production

**Веб-система учёта производства печатных плат:** ведёт заказы по этапам сборки,
автоматически списывает радиокомпоненты со склада по технологической карте
и собирает заявку на закупку в Excel.

## Задача

Небольшое производство электроники вело учёт в таблицах: сколько плат каждого типа
сейчас на каком этапе сборки, сколько компонентов осталось на складе и что пора
закупать под новый заказ. Данные расходились, компоненты «заканчивались» неожиданно,
а заявку на закупку считали руками.

Система закрывает этот процесс целиком: производственная цепочка описывается один раз
в админке, дальше склад списывается сам, а заявка на закупку формируется по нажатию кнопки.

## Что умеет

- **Учёт заказов (приложений).** Заказ заводится один раз с количеством плат каждого типа —
  система сама раскладывает его по всем этапам производства.
- **Движение плат по этапам.** Оператор отмечает, сколько плат перешло на следующий этап;
  из предыдущего этапа это количество списывается. Перевести больше, чем есть, нельзя —
  форма вернёт ошибку и не сохранит данные.
- **Автоматическое списание склада.** У каждой пары «плата + этап» есть техкарта:
  какие компоненты и в каком количестве расходуются. При переводе плат компоненты
  списываются по формуле `остаток − (норма × количество плат)`.
- **Контроль неснижаемого остатка.** На главной странице — компоненты, которых осталось
  меньше критического количества.
- **Заявка на закупку в Excel.** По всем новым заказам считается потребность в компонентах
  и выгружается `.xlsx`-отчёт с колонками «нужно заказать» и «есть на складе».
- **Живое обновление количеств** на странице платы через AJAX, без перезагрузки.

## Стек

| Слой | Технологии |
|---|---|
| Backend | Python 3.12, Django 5.0 |
| БД | PostgreSQL 13 |
| Отчёты | pandas, openpyxl |
| Инфраструктура | Docker Compose, nginx, gunicorn |
| CI/CD | GitHub Actions: flake8 → сборка образа → push в Docker Hub → деплой по SSH → уведомление в Telegram |

На каждый push в `main` прогоняются линтер и сборка образа. Деплой на сервер — отдельный
ручной запуск (`Run workflow` во вкладке Actions): он требует доступного по SSH сервера
с внешним IP.

## Модель данных

Шесть сущностей, из которых собирается любой техпроцесс:

| Модель | Что описывает |
|---|---|
| `Component` | Компонент на складе: остаток, критический остаток, номер партии |
| `Board` | Тип платы (круглая, центральная, лицевая, индикаторная) |
| `Stage` | Этап производства и его порядковый номер в цепочке |
| `Document` | Заказ: номер приложения и количество плат каждого типа |
| `Production` | Сколько плат данного заказа сейчас находится на данном этапе |
| `StageComponentBoardQuantity` | Техкарта: «плата + этап → компонент, норма расхода» |

Порядок этапов задаётся полем `order` — благодаря этому цепочка производства
меняется из админки, без правок кода.

## Структура проекта

```
uv_prod/
├── homepage/     — главная: компоненты ниже критического остатка
├── catalog/      — склад компонентов (+ JSON-эндпоинт для таблицы)
├── production/   — движение плат по этапам, списание склада, техкарты
├── shopping/     — расчёт потребности и выгрузка заявки в Excel
└── templates/    — шаблоны интерфейса
nginx/            — конфигурация reverse proxy
.github/workflows — CI/CD пайплайн
```

## Запуск

1. Клонировать репозиторий:

```bash
git clone https://github.com/moritys/ultraviotet_production.git
cd ultraviotet_production
```

2. Создать `.env` в корне по образцу `example.env`.

3. Поднять контейнеры:

```bash
docker compose up -d --build
```

4. Выполнить миграции и создать администратора:

```bash
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py collectstatic --no-input
```

Приложение доступно на `http://localhost`, админка — на `/admin/`.

> Деплой в CI/CD подключается к серверу по SSH, поэтому требует внешнего IP —
> на локальный сервер за NAT он не пройдёт.

## Порядок работы в системе

**Первичная настройка (один раз, через админку):**
1. Завести типы плат.
2. Завести этапы производства и их порядок.
3. Завести компоненты и остатки на складе.
4. Заполнить техкарты: плата — этап — компонент — норма расхода.

**Регулярная работа:**
1. Завести новый заказ: номер приложения и количество плат.
2. Отмечать переход плат с этапа на этап — компоненты списываются автоматически.
3. Когда заказ отгружен заказчику, он помечается выполненным и уходит со страницы
   производства и из расчёта закупки, оставаясь в админке.
